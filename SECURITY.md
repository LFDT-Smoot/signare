# Security Policy

## Reporting a vulnerability

Please do not open a public GitHub issue, pull request or discussion for a security vulnerability.

Report it privately from this repository's **Security** tab using *Report a vulnerability*. This files a draft advisory visible only to the maintainers and to you. See GitHub's guide on [privately reporting a security vulnerability](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately). Reports are also always accepted by email to the LF Decentralized Trust security list, [security@lists.lfdecentralizedtrust.org](mailto:security@lists.lfdecentralizedtrust.org), as its [security policy](https://github.com/LF-Decentralized-Trust/governance/blob/main/tac/governing-documents/security.md) provides. Name Signare in the email and include the details below. If triage finds a vulnerability, the security team opens a GitHub security advisory for it.

Please include a description of the flaw and the impact you believe it has, the affected version or commit, steps to reproduce, and which signing backend is in use, since the key handling paths differ. Do not include real private keys or production credentials in a report.

Confirmed vulnerabilities are patched and released with a public advisory describing the impact, crediting the reporter unless they ask otherwise. Please allow maintainers time to investigate and release a fix before disclosing publicly.
