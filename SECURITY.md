# Security Policy

## Reporting a vulnerability

Please do not open a public GitHub issue, pull request or discussion for a security vulnerability.

Report it privately from this repository's **Security** tab using *Report a vulnerability*. This files a draft advisory visible only to the maintainers and to you. See GitHub's guide on [privately reporting a security vulnerability](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately). If that option is not available to you, or the report concerns more than this repository, follow the Linux Foundation's [guidance on reporting vulnerabilities to LF projects and foundations](https://www.linuxfoundation.org/security).

Please include a description of the flaw and the impact you believe it has, the affected version or commit, steps to reproduce, and which signing backend is in use, since the key handling paths differ. Do not include real private keys or production credentials in a report.

Confirmed vulnerabilities are patched and released with a public advisory describing the impact, crediting the reporter unless they ask otherwise. Please allow maintainers time to investigate and release a fix before disclosing publicly.
